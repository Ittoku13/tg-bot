# Дизайн: Telegram-бот для группы (игра «Олег дня», характеры, скачивание видео, мок-ответы, мини-апп админка)

Дата: 2026-11-10
Статус: утверждён пользователем

## 1. Контекст и цели

Бот для личной Telegram-группы. Функциональные направления:

1. **Игра «Олег дня»** — ежедневный автоматический выбор случайного участника чата, которому присваивается роль (по умолчанию «Олег», настраивается). Ведётся рейтинг «кто сколько раз был Олегом».
2. **Характеры бота** — два переключаемых стиля текстов: цензурный и 18+ (с матами). ИИ не используется, только библиотеки фраз.
3. **Скачивание видео** — автоматическая реакция на строго отфильтрованные ссылки YouTube/Instagram: скачивание (yt-dlp), обжатие (ffmpeg) под лимит Telegram, отправка видео в чат.
4. **Мок-ответы** — ответы на обычные сообщения чата в стиле искажения букв: на «Я эйчар и запрещаю удалёнку и гибрид» бот отвечает «Я эйчал и заплесяю удаёнку и гиблид». Частота реакций настраивается.

Управление — через **Telegram Mini App** (админка). Развёртывание — **docker compose** на VPS с доменом. В проекте ведётся git-версионирование.

## 2. Принятые решения (фиксируем, чтобы не переобсуждать)

| Вопрос | Решение |
|---|---|
| Стек | Python 3.12+, aiogram 3, long polling, SQLite, FastAPI (встроенный), Caddy, Docker Compose |
| Выбор «Олега» | Автоматически, раз в день в заданное время (по умолчанию 12:00, часовой пояс Europe/Moscow) |
| Пул кандидатов | Пользователи, хоть раз написавшие в чат (бот не может получить список участников группы). Боты исключаются. Вчерашний «Олег» по умолчанию не участвует (настройка) |
| Рейтинг | Считается агрегацией из истории выборов. Просмотр: всё время / месяц / неделя. Сброс — только админ, через мини-апп |
| Характеры | 2 шт.: `clean`, `adult`. Переключение админами через мини-апп или команду `/character` |
| Видео | Авто-реакция только на `youtu.be/…`, `youtube.com/watch`, `youtube.com/shorts`, `instagram.com/reel|reels|p`. Максимум 720p, MP4. Лимит отправки 48 МБ (запас от 50 МБ Bot API) |
| Мок-ответы | Вероятность срабатывания на сообщение — `mock_chance` % (по умолчанию 3), кулдаун между реакциями в чате — `mock_cooldown_min` мин (по умолчанию 10). 0% = выключено |
| Мини-апп | Vanilla HTML/JS без сборки. Доступ: валидация `initData` + проверка, что пользователь — админ чата. Вход — кнопка Menu (BotFather → Menu Button) |
| Публикация мини-аппа | VPS + домен, Caddy с авто-TLS (Let's Encrypt) |
| Хостинг бота | Тот же VPS, единый docker compose-стек |

## 3. Архитектура

Монолит, один процесс:

- **aiogram 3** — приём апдейтов (long polling), хендлеры команд и сообщений.
- **FastAPI (uvicorn, in-process)** — раздаёт статику мини-аппа и JSON API админки. Порт 8080.
- **Планировщик** — asyncio-задача: раз в минуту сверяется со временем автовыбора, после выбора ждёт следующие сутки.
- **SQLite** — единственное хранилище, файл в volume.

Docker compose-стек (прод):

- `bot` — образ из Dockerfile (`python:3.12-slim` + ffmpeg + yt-dlp), volume `bot-data` (SQLite, логи, опциональный `cookies.txt`), `restart: unless-stopped`.
- `caddy` — reverse proxy `https://<WEBAPP_DOMAIN>` → `bot:8080`, авто-TLS.
- `watchtower` — опционально, автообновление образа (отключается переменной/профилем).

Локальная разработка — `docker compose -f docker-compose.yml -f docker-compose.dev.yml up` (без Caddy) или напрямую `python -m bot`; для проверки мини-аппа — туннель.

## 4. Модель данных (SQLite)

- **users** — `(chat_id, user_id, username, first_name, last_active)`. Обновляется на каждом сообщении в чате.
- **picks** — `(id, chat_id, user_id, picked_at)`. Полная история. Рейтинг — агрегация, отдельные счётчики не хранятся. Сброс рейтинга = `DELETE FROM picks WHERE chat_id = ?`.
- **settings** — `(chat_id PK, role_name, pick_time, character, auto_pick_enabled, exclude_last, mock_chance, mock_cooldown_min)`. Значения по умолчанию: `role_name='Олег'`, `pick_time='12:00'`, `character='clean'`, `auto_pick_enabled=1`, `exclude_last=1`, `mock_chance=3`, `mock_cooldown_min=10`.
- **last_mock** — `(chat_id PK, at)` — время последнего мок-ответа в чате (для кулдауна). Отдельная таблица, чтобы не перегружать settings.

## 5. Функциональные блоки

### 5.1 Игра «Олег дня»

- Планировщик в `pick_time` (TZ Europe/Moscow) выбирает случайного кандидата: `users` чата, не бот, за вычетом вчерашнего выбора (если `exclude_last`). Пустой пул → пропуск дня с логом.
- Объявление — шаблон активного характера: «Сегодня {role} — {имя}! {шутка}».
- `/rating` — топ-10 с inline-кнопками периода: всё время / месяц / неделя.
- `/mystats` — личный счёт и дата последнего звания.

### 5.2 Характеры

- `characters/<name>.yaml`: событие → список фраз. События: `pick`, `video_ok`, `video_fail`, `video_too_big`, `rating_header`, `rating_empty`, `help`, `error`.
- Бот выбирает случайную фразу события из активного характера. Плейсхолдеры: `{name}`, `{role}`, `{count}`, `{url}`.
- Переключение: мини-апп или `/character` (только админы).

### 5.3 Скачивание видео

- **Фильтр URL** (regex): `youtu.be/<id>`, `youtube.com/watch`, `youtube.com/shorts/<id>`, `instagram.com/(reel|reels|p)/<slug>`. Всё остальное игнорируется.
- **Пайплайн**: yt-dlp, формат `bv*[height<=720][ext=mp4]+ba[ext=m4a]/b[height<=720]/b`, во временную папку (volume/tmp). Таймаут на закачку.
- **Обжатие** (если > 48 МБ): ffmpeg, ступени `720p CRF 30` → `480p CRF 33` → `360p CRF 36`, `+faststart`. Не влезло на последней ступени → сообщение «видео слишком длинное».
- **Отправка**: `sendVideo` (streaming), подпись — название ролика.
- **Защиты**: очередь (1 скачивание на чат, глобальный семафор 2), дедупликация одинаковых URL за 10 минут, ретрай 1 раз при сетевой ошибке, удаление временных файлов в `finally`, очистка tmp при старте.
- **Instagram**: публичные reels/p посты качаются; приватные/возрастные — сообщение об ошибке. Поддержка `cookies.txt` через volume (инструкция в README).

### 5.4 Мок-ответы

- **Триггер**: на каждое текстовое сообщение в чате (не команда, не ссылка, пойманная видео-хендлером, не от бота) решается `services/mockery.py`: срабатывает с вероятностью `mock_chance` % и только если с последнего мок-ответа в этом чате прошло ≥ `mock_cooldown_min` минут.
- **Пропускаем**: сообщения короче 10 символов, состоящие только из эмодзи/стикеров, сервисные сообщения, команды, сообщения со ссылками из видео-фильтра.
- **Искажение**: над текстом сообщения выполняются случайные операции — замена буквы на похожую (наборы путаницы: `р/л`, `с/з`, `е/ё/и`, `т/ч`, `б/п`, `д/т`, `н/м`, `о/а`, `в/ф`, `г/к`), редкое удаление буквы или перестановка соседних букв. Затрагивается ~10–20% букв (не больше), длина результата ограничена (максимум ~500 символов, длинное обрезается).
- **Ответ**: reply на исходное сообщение с искажённым текстом, без дополнительных комментариев. Характеры не влияют на искажение (оно строится из текста пользователя).
- Время реакции пишется в `last_mock` (только при срабатывании).

### 5.5 Админка (мини-апп)

- **Доступ**: `initData` из WebApp → HMAC-SHA256 проверка → пользователь должен быть админом чата (`getChatMember`) или `SUPERADMIN_ID`.
- **API** (`/api/…`, JSON):
  - `GET /api/state` — текущие настройки + топ-10 рейтинга;
  - `POST /api/character` — `{character: clean|adult}`;
  - `POST /api/role` — `{role_name}`;
  - `POST /api/pick_time` — `{pick_time: HH:MM}`;
  - `POST /api/auto_pick` — `{enabled: bool}`;
  - `POST /api/exclude_last` — `{enabled: bool}`;
  - `POST /api/mock` — `{mock_chance: 0..100, mock_cooldown_min: int}`;
  - `POST /api/reset_rating` — сброс истории чата (фронт требует подтверждение).
- **Фронт**: одна страница, vanilla JS: формы настроек, переключатели, топ с кнопками периода, кнопка сброса с подтверждением.
- **Вход**: кнопка Menu в Telegram (URL задаётся в BotFather: `https://<WEBAPP_DOMAIN>`).

## 6. Обработка ошибок

- Все пользовательские сценарии ошибок (недоступное/удалённое видео, возрастное ограничение, нужен логин Instagram, сеть упала, не влезло после обжатия) — понятное сообщение из активного характера, без технических деталей.
- Глобальный try/except вокруг обработки апдейта: падение хендлера не роняет бота, ошибка логируется.
- Логи: `logging` → stdout + файл в volume с ротацией по размеру.

## 7. Тестирование

- **pytest, unit-тесты чистой логики** (сеть и Telegram API замоканы):
  - фильтр URL (позитивные/негативные случаи);
  - агрегации рейтинга (топы за периоды, сброс);
  - выбор кандидата (исключение ботов, `exclude_last`, пустой пул);
  - валидация `initData` (валидная/битая подпись, `auth_date` протух);
  - обжатие: выбор ступени по размеру (логика без реального ffmpeg);
  - мок-ответы: искажение текста (только допустимые операции, границы процента букв, короткие сообщения не искажаются), решение о реакции (вероятность, кулдаун, 0% = никогда).
- Сервисы yt-dlp/ffmpeg за интерфейсом-заглушкой.
- **Ручной чек-лист** (в README) на тестовой группу: команды, автовыбор по расписанию, ссылка YouTube, ссылка Instagram, мок-ответы на сообщения, админка в мини-аппе.

## 8. Деплой

1. Клон репозитория на VPS, `cp .env.example .env`, заполнить `BOT_TOKEN`, `SUPERADMIN_ID`, `WEBAPP_DOMAIN`.
2. `docker compose up -d`.
3. BotFather: выключить privacy mode (чтобы бот видел все сообщения — нужно для авто-ловли ссылок и мок-ответов), задать Menu Button URL `https://<WEBAPP_DOMAIN>`.
4. Добавить бота в группу как админа (не обязательно, но рекомендуется).
5. Локально: `python -m bot` или dev-compose; проверка мини-аппа через туннель.

`README.md` содержит пошаговую инструкцию, включая включение `cookies.txt` для Instagram.

## 9. Ограничения (известные)

- Бот не «видит» молчаливых участников группы — пул выбора только из активных.
- Лимит Bot API 50 МБ на отправку видео: очень длинные ролики не влезут даже после обжатия.
- Instagram периодически меняет защиту; без `cookies.txt` часть контента может быть недоступна.
- Мок-ответы случайны по своей природе: с вероятностью 3% бот может «выстрелить» неудачно или, наоборот, долго молчать.
